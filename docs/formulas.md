## 2. 単位・座標系（Excel実測に基づく）

- 大腿長・下腿長・骨盤幅：**cm**（本件のExcelでは52 / 49 / 31が定数入力されている）
- セグメント角度（Euler.y、Euler.x）：**度（degree）**。三角関数適用前に`RADIANS()`でラジアンへ変換している
- 出力される前後成分（AB〜AE、AM、AN、AP、AQ、AR）の単位：**cm**（長さ入力と同じ単位系）
- サンプリング周波数：CSVの`UnixTime`間隔の実測値から**約20 Hz**（フレーム間隔約50ms）。要件定義書第10章の「補間は20Hzを超える実測情報を生成しない」という記述と整合する

## 3. セグメント前後位置

大腿の前後成分を\(P_T\)、下腿の前後成分を\(P_S\)とし、大腿長を\(L_T\)、下腿長を\(L_S\)とする。Excelでは大腿・下腿とも「Single.Euler.y」角度のみを用い、xやzは使用していない。

\[
P_T = \sin(\theta_{T,y}) \times L_T
\]
\[
P_S = \sin(\theta_{S,y}) \times L_S
\]

（\(\theta\)はラジアンに変換した角度。以降も同様）

Excel転記（右側、AB・AD列、row2の例）：

```text
AB2 = SIN(RADIANS(O2)) * Y2      ' 右大腿前後成分 = sin(RightThigh.Euler.y) * 大腿長
AD2 = SIN(RADIANS(G2)) * Z2      ' 右下腿前後成分 = sin(RightLowerLeg.Euler.y) * 下腿長
```

左側（AC・AE列）も同一構造で、列参照のみ`S`（LeftThigh.Euler.y）・`K`（LeftLowerLeg.Euler.y）に置き換える。

## 4. 下肢遠位端前後位置（右下肢距離・左下肢距離）

右下肢距離\(D_R\)、左下肢距離\(D_L\)は、大腿前後成分と下腿前後成分の単純合算。

\[
D_R = P_{T,R} + P_{S,R} = \sin(\theta_{RightThigh.y}) L_T + \sin(\theta_{RightLowerLeg.y}) L_S
\]
\[
D_L = P_{T,L} + P_{S,L} = \sin(\theta_{LeftThigh.y}) L_T + \sin(\theta_{LeftLowerLeg.y}) L_S
\]

Excel転記（AM・AN列、row2の例）：

```text
AM2 = SIN(RADIANS(O2))*Y2 + SIN(RADIANS(G2))*Z2   ' 右下肢距離
AN2 = SIN(RADIANS(S2))*Y2 + SIN(RADIANS(K2))*Z2   ' 左下肢距離
```

これは要件定義書9.1の一般形 \(x_{distal}=f(L_T,\theta_T)+f(L_S,\theta_S)\) に対応し、\(f(L,\theta) = \sin(\theta) \times L\) であることが確定した。

## 5. 骨盤回旋補正

骨盤幅を\(W\)、骨盤の回旋角（`LowerBack.Single.Euler.x`）を\(\phi\)、解析対象トライアルの基準フレーム（Excelでは**CSV先頭データ行＝`$B$2`固定参照**）における値を\(\phi_0\)とすると、骨盤回旋補正量\(C\)は以下となる。

\[
C = \sin(\phi - \phi_0) \times W
\]

Excel転記（AP列、row2・row150の例）：

```text
AP2   = SIN(RADIANS(B2   - $B$2)) * AA2   ' row2はφ=φ0なのでC=0
AP150 = SIN(RADIANS(B150 - $B$2)) * AA150
```

**基準フレーム\(\phi_0\)は、解析対象CSV全体の最初のデータ行（1行目）の値に固定**されている。区間を切り出して解析する場合でも、この基準は「CSV全体の先頭行」であり「解析区間の先頭行」ではない点に注意する（第11章「残された未確定事項」参照）。

## 6. 歩幅（骨盤補正なし／あり）

元の符号付き歩幅\(S\)（骨盤補正なし、Excel AQ列）は、左下肢距離から右下肢距離を引いた値。

\[
S = D_L - D_R
\]

骨盤補正あり歩幅\(S_{corr}\)（Excel AR列）は、これに骨盤回旋補正量を加算する。

\[
S_{corr} = S + C
\]

Excel転記（AQ・AR列）：

```text
AQ2 = AN2 - AM2     ' 骨盤補正なし歩幅 = 左下肢距離 − 右下肢距離
AR2 = AQ2 + AP2     ' 骨盤補正あり歩幅 = 骨盤補正なし歩幅 + 骨盤回旋補正量
```

この符号は要件定義書3章の用語定義「元の符号付き歩幅：左下腿遠位端が右下腿遠位端より前方にある場合を正」と一致する（\(D_L>D_R\)のとき\(S>0\)）。

## 7. IC側基準歩幅・絶対歩幅への変換

Excelには含まれないため、要件定義書9.2の定義をそのまま採用する。骨盤補正なし・ありの両方について同じ変換を適用する。

\[
S_{RtIC} = -S, \qquad S_{LtIC} = S
\]
\[
S_{abs} = |S|
\]

## 9. 角度の符号方向（動画照合により確定）

`Single.Euler.y`（大腿・下腿とも）の正負方向を、`test-data/subject01_raw.csv`に対応する動画「Itose2_快適　左.mp4」の実フレームと照合して確認した。

証拠として使用したフレーム画像（`docs/assets/`）は、匿名化されていない実際の被験者動画から切り出したものであるため、技術提案書15章の方針に従いリポジトリには含めていない（`.gitignore`で除外）。ローカルの作業フォルダにのみ保存されている。

### 9.1 照合方法

1. 動画をffmpegでフレーム抽出し、被験者が画面内に映る区間（動画時刻 約7.0〜11.5秒）を特定した。
2. その区間内の2時点（動画時刻7.77秒・8.00秒）について、CSVの対応行（暫定的に動画全体とCSV全体を1:1対応させた時刻、第10章参照）における`RightThigh.Single.Euler.y`・`LeftThigh.Single.Euler.y`・`RightLowerLeg.Single.Euler.y`・`LeftLowerLeg.Single.Euler.y`の値を取得した。
3. 同時刻の動画フレーム上の姿勢（どちらの脚が前方に踏み出し／後方に伸展しているか）と、角度の符号を比較した。

### 9.2 照合結果

| 動画時刻 | 観察された姿勢 | CSV値（該当行） | 符号との対応 |
|---|---|---|---|
| 7.77秒（`docs/assets/angle_sign_evidence_t7.77s_pushoff.png`） | 片脚が体幹より後方へ伸展し、踵が浮いた立脚終期（push-off直前）の姿勢。もう片脚は前方へ大きく振り出された遊脚中期の姿勢 | 後方に伸展した脚側：下腿角度 −51.6°（強い負）、大腿角度 −6.4°（弱い負）／ 前方に振り出された脚側：大腿角度 +33.1°（強い正）、下腿角度 +3.7° | 後方伸展＝負、前方振り出し＝正 |
| 8.00秒（`docs/assets/angle_sign_evidence_t8.00s_initialcontact.png`） | 片脚が踵接地し前方に伸びた初期接地の姿勢。もう片脚は体幹より後方で爪先立ちの立脚終期の姿勢 | 前方の脚側：下腿角度 +16.4°（正） ／ 後方の脚側：下腿角度 −8.3°（負） | 前方＝正、後方＝負（7.77秒時点と同一の脚が入れ替わって再現しており、再現性を確認） |

2時点で「前方へ振り出された脚は正、後方へ伸展した脚は負」という対応が一貫して再現された。これは歩行の生体力学的知見（遊脚期の股関節屈曲・下腿前方振り出しが正、立脚終期の股関節伸展・下腿後方傾斜が負となる一般的な角度定義）とも整合する。

### 9.3 確定した符号規約

- **大腿（Thigh）Euler.y**：正＝大腿が前方（遊脚期の股関節屈曲方向）へ傾斜、負＝大腿が後方（立脚終期の伸展方向）へ傾斜
- **下腿（LowerLeg）Euler.y**：正＝下腿が前方へ傾斜、負＝下腿が後方（push-off時）へ傾斜

この符号のまま`sin(θ)×長さ`を前後成分として使用する既存Excelの計算式（第3〜4章）は、動画で確認した実際の前後方向と整合しており、**符号反転や補正は不要**と判断する。

### 9.4 照合上の注意・残る限界

- 動画中で「右脚」「左脚」のどちらが解剖学的にRt/Ltに対応するかは、単一カメラの側面映像だけからは断定できなかった。ただし今回の確認で重要なのは符号の物理的な向き（前方＝正／後方＝負）であり、これはCSVの列がRt/Ltいずれであっても成立する一般的な結論である。列とセンサー装着部位の対応そのものは、データ収集プロトコル側（OpenCap／IMU側)の管理範囲であり、本アプリはCSVの列ラベルをそのまま信頼する前提とする。
- 上記の対応時刻（動画7.77秒・8.00秒）は、後述10章で判明した「動画全体とCSV全体の単純比例同期は本データでは成立しない」という制約のもとでの暫定対応であるため、厳密な時刻一致ではなく、歩行相（push-off／初期接地）という比較的長く続く姿勢区間内での整合を確認したものである。将来、正確な同期方式（1点または2点同期）が確定した際に、再確認することが望ましい。

## 10. 動画・CSV同期に関する発見と対応方針

Phase 0の照合作業中に、要件定義書7.1・技術提案書8章で規定される「動画全体の0〜100%とCSV全体の0〜100%を対応させる」比例同期について、以下を確認した。

- 動画「Itose2_快適　左.mp4」の長さは15.24秒（30fps）
- CSVの総継続時間は約15.2秒（約20Hz、305データ行）
- 両者の長さはほぼ一致するが、動画内で被験者が画面に映っているのは動画時刻 約7.0〜11.5秒の区間のみ（固定カメラの画角が歩行経路の一部しか捉えていないため）
- CSV側は動画開始とほぼ同時刻（CSV時刻 約1.0秒）から歩行に伴う角度振動が始まっており、CSV全体を通じて継続的に歩行データが記録されている
- ただし、比例同期のまま被験者が画面内に映っている区間（動画7.77秒・8.00秒）のCSV値を確認したところ、第9章のとおり歩行相として矛盾のない値が得られた。すなわち、少なくともこの区間内では比例同期のずれは実用上問題にならない範囲に収まっている

**対応方針（2026年9月11日、利用者確認済み）**：被験者が動画に映っていない区間は、そもそもイベント登録や解析の対象にしない。検者は動画を見ながらイベントを登録するため、被験者が画面外の区間でイベントを登録することは実運用上発生しない。したがって、CSV全体のうち動画に被験者が映っていない区間の同期精度は、MVPの機能要件上は問題にならない。

この方針により、比例同期（要件定義書7.1）をMVPのまま維持してよいと判断する。ただし、以下は今後も有効な設計指針として維持する。

- 動画に被験者が映っていない区間でも、CSVデータの読込・表示自体は妨げない（検者が誤ってイベント登録しようとした場合に警告できることが望ましい程度で、必須ではない）
- 同期情報表示（要件定義書7.2）・警告閾値（7.3）は、比例同期のずれを検者が視認できるようにするための重要な安全弁として、引き続き必須要件とする
- 1点／2点同期（7.4）は、将来的な精度向上のための拡張として位置付けを維持する（優先度の引き上げは不要）

## 11. 残された未確定事項

角度の符号方向（旧・第9章の論点）は第9章で確定したため、以下のみが未確定として残る。

- **骨盤回旋補正の基準フレーム**：現状「CSV全体の先頭行」固定。アプリで任意区間を切り出して解析する場合、この基準を「CSV先頭」のまま踏襲するか、「解析対象区間の先頭」に変更するかは要決定。本書では既存Excelの挙動（CSV先頭固定）をデフォルトとして踏襲し、設定で変更可能な設計とすることを推奨する。
- **左右別の大腿長・下腿長**：本Excelでは左右共通値（Y・Z列がそのまま両側に使用されている）。要件定義書4.3の「左右別長さへの拡張」は将来対応。
- **Off（離床）に関する計算式**：Excelには歩幅計算のみが含まれ、Off検出やイベント判定に関する式は存在しない。イベント登録はアプリ側の手動操作（第8章）による。
- **動画・CSV同期方式**：第10章のとおり、被験者が画面外にいる区間を解析対象外とする方針が確定したため、比例同期のままMVPを進める。解決済み。
